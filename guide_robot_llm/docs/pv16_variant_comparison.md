## 2. Методика и оговорки

- Метрики берутся из `score.json` каждого run (`variants.<V>`), воспроизводятся
  перескорингом (раздел 8).
- `unjudged` — кейсы, где скорер не смог извлечь ответ (freeform без числа) или
  нет gold. Denominator метрик = n в скобках, **не** 32/15.
- `parse_failed` — строгий JSON deployed-формата не получен (для P-вариантов
  qwen3.5).
- `engaged_*` — только на 7 синтетических кейсах (n ≤ 7) — ориентир, не итог.
- D-трек: автометрик нет (claims записываются для ручной оценки), сравнение —
  формат + стоимость + parse.

## 7. Наблюдения

1. **P_base (production) — худший pointing у всех 4 моделей** (pass 0.2–0.33,
   top-2 0.067–0.267; абстинкция 1–9/15, у e4b — 60%); все 6 новых вариантов
   выше. Самый устойчивый выигрыш — P1 (grounding + abstain) и P4: 1 вызов,
   top-2 0.4–0.5 без parse-проблем у gemma.
2. **CoT-2pass (A2/P2) даёт лучший count/top-2 у gemma4-e4b и qwen3.5-9b**, но
   A2 ломает qwen3.5-4b (MAE 1.5, within±1 0.5) и P2 — strict-JSON qwen3.5
   (parse_failed до 7/15). Техника «дорогая и модель-зависимая».
3. **Loop (A3/P3)** не даёт устойчивого выигрыша над одно-вызовными: A3 ≈ A0/A2
   при 2.8–3.0 вызовах (и хуже у 9b), P3 — лучший pass у gemma за 3 вызова
   (p50 4.2–8.5 c) и слабее у 9b.
4. **Аблации**: A4 (без «сомнительных → не готов») ≈ A1 у 9b/4b, но у e4b
   извлечение числа деградирует (28/32 unjudged) — правило работает как
   форматный якорь. P4 (без abstain-линии) ≈ P1.
5. **A0 (минимум) — самый стабильный A-вариант по моделям** (0.586–0.906,
   1 вызов, < 1 c p50); A_base (deployed) быстрее всех (0.34–0.54 c) и силён у 9b.
6. **Engaged-подсчёт лучше у qwen3.5** (MAE 0.25–1.0, exact до 0.75) чем у gemma
   (1.0–3.0); n ≤ 7 — только ориентир.
7. **D-варианты форматно нейтральны** (5/5 claims, 0 на unanswerable); выбор —
   по ручной оценке качества + задержка (D_base минимальна, D2 в 2× дороже).
8. `unjudged` у gemma в freeform (до 28/32) — скоринг извлекает числа из текста;
   для gemma-freeform это источник потерь в измерении, не только качества.
